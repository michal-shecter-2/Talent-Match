# Talent — React + Node.js + SQL Server

מערכת בעברית להתאמת מועמדים, עם הרשמה עצמית וחשבון נפרד לכל מגייסת. מאגר המועמדים, השמורים והיסטוריית החיפושים פרטיים לכל חשבון.

## הפעלה מקומית

דרושים Node.js 22.12 ומעלה או Node.js 24, ו־SQL Server 2016 ומעלה שנגיש בחיבור TCP.

1. צרי מסד נתונים בשם `Talent` דרך SSMS:

```sql
CREATE DATABASE Talent;
```

2. העתיקי את `.env.example` לקובץ מקומי בשם `.env` ומלאי את `DB_SERVER`, `DB_PORT`, `DB_NAME`, `DB_USER` ו־`DB_PASSWORD`. אין להעלות את הקובץ ל־Git או לשלוח סיסמאות בצ'אט.

3. התקיני את החבילות וצרי את הטבלאות:

```sh
npm ci
npm run db:migrate
```

המשתמש שמפעיל את המיגרציה צריך הרשאות יצירת טבלאות. להפעלה שוטפת אפשר להשתמש ב־SQL Login נפרד עם הרשאות קריאה וכתיבה רק לטבלאות המערכת.

4. פתחי שני טרמינלים מתוך תיקיית הפרויקט:

```sh
npm run dev:server
```

```sh
npm run dev
```

5. היכנסי ל־`http://localhost:5173`, לחצי על **חדשה כאן? יצירת חשבון אישי**, והירשמי עם שם, אימייל וסיסמה של לפחות 12 תווים. כל חשבון מקבל מאגר ריק ונפרד.

ברירת המחדל היא הרשמה עצמית (`REGISTRATION_ENABLED=true`). אין משתמש או סיסמת ברירת מחדל. חיבור SQL נעשה בשרת בלבד, באמצעות SQL Authentication. Windows Authentication אינו מוגדר בגרסה הזאת.

בשרת SQL מקומי עם תעודה עצמית, ניתן להגדיר בפיתוח בלבד `DB_TRUST_SERVER_CERTIFICATE=true`. ב־Production היישום דורש חיבור מוצפן ותעודה מהימנה.

## עבודה ושמירה

אחרי טעינת אקסל, סימון מועמדים או חיפוש, לחצי על **שמירת השינויים** בסרגל העליון. הנתונים נשמרים ב־SQL Server ונטענים בכניסה הבאה. ביציאה רגילה, שינויים נשמרים לפני היציאה. רענון עם שינויים שלא נשמרו מציג אזהרה בדפדפן.

השמירה ידנית ומצבה מוצג במסך. שמירה ישנה מלשונית אחרת נדחית כדי למנוע דריסה שקטה. במקרה של התנגשות, יש לשמר מידע חדש לפני רענון.

כולל טעינת XLSX ו־CSV, מיפוי עמודות, חיפוש, כרטיסי מועמדים, שמורים וייצוא CSV. החיפוש עדיין משתמש בהדגמת חפיפת מילות מפתח; **Gemini טרם חובר**.

## משתמשים ואימות

- הרשמה עצמית, כניסה, זיהוי אחרי רענון ויציאה.
- גיבוב סיסמאות עם salt ו־scrypt; אין סיסמאות גלויות במסד.
- session אקראי בעוגיית HttpOnly, עם גיבוב במסד ותפוגה של 8 שעות.
- בדיקת חשבון פעיל והרשאות בכל בקשה מוגנת.
- הגבלת ניסיונות כניסה לפי IP וחסימת חשבון זמנית אחרי ניסיונות כושלים.
- הגנת בקשות שמשנות נתונים באמצעות Origin תואם וכותרת `X-Talent-Request: 1`.

בגרסה הזאת אין אימות בעלות על אימייל או איפוס סיסמה במייל. ההרשמה מאמתת את מבנה האימייל בלבד. מגבלת ה־IP בזיכרון מתאימה לתהליך Node אחד; פריסה עם כמה תהליכים תדרוש מגבלה משותפת.

## SQL Server

| טבלה | תוכן |
| --- | --- |
| `Users` | שם, אימייל ייחודי, גיבוב סיסמה ומצב חשבון |
| `UserSessions` | גיבוב session, מזהה משתמשת ותפוגה |
| `RecruiterWorkspaces` | מזהה בעלים, נתוני העבודה כ־JSON ומספר גרסה |

הבעלים נקבע בשרת לפי ה־session. מזהה מגייסת שמגיע מהלקוח אינו משמש לבחירת הנתונים. השאילתות משתמשות בפרמטרים.

בשלב הזה נשמרת רשומת JSON אישית, עד 5,000 מועמדים, 10MB ו־30 חיפושים. במאגר גדול יותר אפשר לפצל לטבלאות מועמדים, מיומנויות וחיפושים.

## API

| שיטה | כתובת | פעולה |
| --- | --- | --- |
| GET | `/api/auth/config` | הגדרת הרשמה |
| POST | `/api/auth/register` | הרשמה בתפקיד מגייסת |
| POST | `/api/auth/login` | כניסה |
| GET | `/api/auth/me` | המחוברת הנוכחית |
| POST | `/api/auth/logout` | ביטול session |
| GET / PUT | `/api/workspace` | קריאה ושמירה של מאגר אישי |

React וה־API עובדים באותו origin. בפיתוח Vite מעביר את `/api` לפורט 3001. `APP_ORIGIN` חייב להתאים לכתובת שנפתחת בדפדפן.

קיים גם ניהול חשבונות אופציונלי למנהלת דרך `/api/admin/users`. יצירת מנהלת נעשית מקומית עם `npm run user:create`, בהזנת סיסמה מוסתרת בטרמינל. הרשמה עצמית תמיד יוצרת מגייסת. גם מנהלת אינה מקבלת גישה למאגר של חשבון אחר.

## בדיקות

```sh
npm test
npm run build
```

בדיקות ה־API משתמשות במאגר בדיקה בזיכרון ומכסות הרשמה, session, הרשאות, הפרדה בין מגייסות, בקשות ממקור אחר, התנגשות שמירה ויציאה. הן אינן מאמתות חיבור SQL Server חי.

אחרי הגדרת מסד **פיתוח** והרצת המיגרציה:

```sh
npm run test:sql
```

בדיקה זו יוצרת שני חשבונות ייחודיים, בודקת את שאילתות המשתמשים, ה־sessions, המאגרים והגרסאות, ואז מוחקת רק אותם. אין להריץ מול Production.

## תצוגת UI ללא שרת

פתחי את `talent-preview.html` בכרום ללא התקנה. יש שני חשבונות פיקטיביים וקישור למסך הרשמה. ההדגמה אינה יוצרת חשבונות או שומרת ב־SQL Server; הנתונים מתאפסים ברענון או בהחלפת חשבון.

```sh
npm run build:preview
```

ההדגמה נבנית בנפרד ב־`dist-preview`. הבנייה הרגילה ב־`dist` דורשת כניסה אמיתית, ושרת ה־API אינו מקבל חשבונות הדגמה.

## פריסה ומבנה

הריצי `npm run build`, ואז `npm start`. Node מגיש את React ואת ה־API. בפריסה יש להגדיר `NODE_ENV=production`, כתובת HTTPS ב־`APP_ORIGIN` ללא לוכסן מסיים, וחיבור SQL מוצפן עם תעודה מהימנה. `TRUST_PROXY_HOPS` מיועד למספר שרתי ה־proxy המהימנים בתשתית.

| קובץ | תפקיד |
| --- | --- |
| `src/AuthGate.tsx` | מסכי הרשמה וכניסה |
| `src/App.tsx` | סביבת עבודה ושמירה |
| `src/services/api.ts` | קריאות לשרת |
| `server/app.mjs` | API והרשאות |
| `server/user-repository.mjs` | שאילתות משתמשים ו־sessions |
| `server/workspace-repository.mjs` | תיקוף ושמירת מאגר אישי |
| `server/schema.sql` | טבלאות המסד |
| `server/passwords.mjs` | גיבוב סיסמאות |

מקורות: [Node Crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html), [node-mssql](https://tediousjs.github.io/node-mssql/), [Express Security](https://expressjs.com/en/advanced/best-practice-security/).
